## 代码结构复核与后续优先级

本轮沿着实际操作重新核对了以下边界；文章能力的整体设计、协议与实现记录继续以 [DeepSeek 能力报告](2026-11-14_deepseek-capabilities-results.md)为准。

| 链路与入口 | 当前结构与本轮判断 |
|---|---|
| `App` → `DesktopShellLayout` / `desktopShellStore` | 顶层页面切换由 store 管理；SettingsView 保留已访问设置页。页面保留与草稿保留是不同职责，异步结果仍需各模块校验归属 |
| `GeneralSettings` → `generalSettingsStore` | 账户信息只读；加载/保存失败与编辑草稿分开。重连保留草稿，账号变化与请求代次隔离迟到结果。此前原生断连/重连结果仍有效，本轮未重复改写该模块 |
| `LibraryUploadDialog` → `libraryDraftStore` → `LibraryView` → `libraryApi` | 文件句柄由内存草稿持有，实际网络请求由父视图管理；本轮只统一选择器的显示来源并收紧确认期间的提交入口，保留既有成功/失败处理 |
| `BackupFileImportRow` → `serverApi.dataTransfer` → `routes/dataTransfer.ts` | 选择、识别、提交和结果有独立状态与导航代次；导入后刷新元数据而不启动任务。原生重复 ZIP 导入尚未走完，不能以函数级去重测试替代 |
| `DesktopChatArea` → `DesktopCheckpointNotice` → `useSidecarAgentRun` | 快照 UI 按会话/运行 key 重建，并校验会话归属和忙碌状态。最终覆盖仍是独立确认动作，原 QA 不应为构建新包而重启 |
| `tauriBridge` → Rust dialog / Sidecar | 原生能力集中封装；前端状态问题不能用放宽文件筛选、目录边界或权限来修补。本轮保留 Rust 原字节 |
| Provider 适配器、Search/Fetch、OCR、provider state | 文章借鉴已经落到共用适配、显式费用确认、结构化引用与持久化边界。本轮没有重新验证真实 DeepSeek 付费质量，也未用累计 token 数直接推导优化收益 |

另有一项明确的部署边界：当前备份识别/导入 API 接收桌面选出的 `filePath`，服务端对这个路径执行 `stat` 并读取。它要求服务端能访问同一路径。本机 QA 符合这一条件；远程服务器部署不能直接视为同样可用。远程文件传输需要单独设计受限上传、临时文件和清理流程，本轮没有悄悄扩展这套接口。

下一步优先完成候选原生复验，再继续备份 ZIP 重入与资料上传完整链路。实机无法稳定复现的旧实例现象先保留证据，不通过猜测修改底层架构。

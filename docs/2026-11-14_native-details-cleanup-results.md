## 细节修复及复验

`LibraryView.tsx` 原来对任何 `document.errorCode` 都渲染红色 alert。`library_cloud_required` 在已有状态行中明确表示“原件已保存，需要云端文字识别后才能检索”，详情下方也已有下载原件/选择 OCR 的说明，因此重复的红色错误容易让人误以为原件丢失或上传失败。

此次只让这个结构化代码跳过重复的红色 alert，保留状态与下一步指引。没有更改服务端状态、原件、索引、OCR 调用或计费行为。

重新构建并真实打开新包后，图片和 Office 原件的详情都显示中性状态及 OCR 指引。为核对其他失败仍有反馈，通过独立 QA 的本机 API 放入一份生成的无效 UTF-8 文本，得到 `library_invalid_text`，再实际进入原生资料库查看，红色错误和恢复说明仍清楚可见。该无效文本是 API 预置数据，**没有将它算作原生上传通过**。

修改后的独立候选树桌面回归为 **684 pass / 0 fail**，全仓 typecheck、Biome、UI 构建和 Tauri debug app 构建通过，原工作区 Biome 也通过。本轮没有改 server/Sidecar/Rust 源码，没有把此前这些模块的测试写成本轮重跑结果。已有大 chunk 构建提示仍保留。

## 实际清理范围

清理前先验证隔离工作树的 20 个脏路径与主线已保存内容一致，候选基线提交树也与此前发布基线一致，没有独有未发布代码。

- 停止仅属于本任务的 QA 宿主、Sidecar 和独立后端；验证 59329 不再监听。
- 删除本任务隔离工作树与对应的临时候选分支；其他已有工作树和旧的可清理注册项没有被顺带处理。
- 删除任务审计临时目录，清理前 `du` 为 **3,789,056 KiB，约 3.6 GiB**。其中包含生成文件、独立数据库与上传目录、私有运行环境、原始诊断日志、构建包、代码副本和对照材料。这个数字是目录清理前占用，不作为严格的物理磁盘释放量。
- 清理三个专用应用标识 `com.openhorn.nativeqa`、`com.openhorn.review`、`com.openhorn.nativereview` 的已存在 WebKit 数据、缓存、偏好与日志，并撤销临时包注册。
- 仅匹配快照 manifest 的 `workspaceRoot` 位于任务临时目录内的专用 bucket，删除其中三份生成快照；没有清空全局 snapshots。
- 删除八份已知属于本任务的 `/tmp` 指针、状态记录和进程采样文件。

清理后核对：任务目录与指针不存在；已发现的专用应用存储路径不存在；独立端口关闭；原应用进程与 3002 后端监听进程保持原身份；273 个原有修改/未跟踪路径除预期记忆更新外保持原字节。主项目的运行包、安装依赖、原数据库、真实会话和其他未提交工作没有被清理。

## 保留边界

- 此前的最终 GUI 文件快照还原没有执行；专用合成工作区和快照现已按用户要求清理，因此不再等待这个旧环境中的还原，也不把它记为 GUI 还原通过。
- 真实 DeepSeek 付费 OCR 质量/账单、实际中文输入法候选选择、自动调度运行仍不是本轮已验收项目。
- 原生系统范围菜单没有被截图可靠捕获，本轮仅确认键盘切换后的值与内容，不推断其展开配色。
- 远程后端无法直接读取桌面本地 `filePath` 的部署边界仍需单独处理；本机成功不能算远程导入验收。

## 真实实验

固定模型 `jev-1.14.0`，原生 `https://api.typesafe.ai/v1/systemone`，使用服务端 `TYPESAFE_API_KEY`。全部付费调用仅发送自编原文/说明，没有发送用户私有评论、聊天记录、项目代码或凭据。

32组配对来自16条评论，每条有正误说明；探索集16组、留出集16组使用不同评论。覆盖中文、英文、日文、反话、否定、混合评价、问题与事实的区别、传闻归属、承诺与实际结果、原文中的提示注入。预期标签由本会话人工指定，未经过独立标注者复核。

## 如何使用

后端环境配置 `TYPESAFE_API_KEY` 并加载更新后的前后端，进入 **工作台 → 评论分析 → 点击评论原文 → 用 Jev 核对说明**。仅非空、已保存的说明可检查；有草稿改动时需先保存。用户点击前可见发送范围，完成后可展开查看实际请求内容。

- 支持概率≤0.3：建议复核说明。
- 支持概率≥0.7：未发现明显冲突。
- 中间：判断不确定。

这是一条辅助信号；不自动修改/拒绝标注，不阻塞导出，不核对情绪和主题。仅发送该条完整原文和已保存说明，不发送评分、主题、文件名或聊天上下文。

## 可靠性与边界

- `shared/review-note.ts` 集中定义模型、问题、版本和阈值。API只在服务器调用，固定HTTPS endpoint、禁止重定向、10秒超时，没有自动重试。密钥不进入API响应、前端、请求预览、日志或评测数据；产物密钥扫描为0匹配。
- HTTP错误、超时、错误模型、非法概率或usage均为结构化错误，不能解释成概率0。空说明、未保存的修改和过长请求在调用前拒绝。
- 检查记录保存在对应评论的`noteVerification`，绑定annotationRevision/模型/问题版本。当前版本命中成功缓存时不再调用；同requestId丢失ACK重试可读回成功记录。外部改动造成旧版本时拒绝，避免把别人的新说明结果当作旧编辑草稿结果。
- 同进程写锁覆盖调用流程，但网络期间不持SQL事务。返回后重新检查文档revision、annotationRevision和实际发送的原文/说明，才以CAS保存，覆盖独立复现的“删除后以同ID/同revision恢复”ABA场景。
- 调用前为检查元数据预留1 KiB配额，写回再次完整校验12 MiB文档上限。调用成功后CAS冲突或网络结果未知时，不承诺精确一次计费；没有自动重放付费请求。
- 手动保存或AI重新标注会清除旧检查；旧文档无需迁移，备份验证/恢复保留合法检查记录。详情仅在自己成功检查的ACK后更新保存基线；迟到响应不能跨视图显示旧弹窗或更改导航。

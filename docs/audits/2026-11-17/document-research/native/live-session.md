# 提交后原生桌面实测

日期：2026-11-17，Asia/Shanghai。真实请求使用已有 gpt-6-astra 渠道；搜索沿用当前 Tavily，不修改搜索凭据。运行时修复：50912fc；中文排版修复：2d14ab5。

## 研究：真实失败、修复与复测

1. 在 OpenHorn 原生桌面点击“新会话”，展开浅色模式菜单，选择“深度研究”，填写 Tavily Search API basic/advanced 差异问题后发送。
2. 展开执行过程，观察到两次 `Search · Tavily` 和一次指定官方 URL 的 `Fetch`。首轮约 41 秒时出现报告式的中间分析，随后额外生成结束于失败，数据库状态为 failed，正式正文为空。该次不能计为成功。
3. 离线复核首轮结构化来源与中间文本，确认该文本本已符合来源校验。修复为：满足两次成功搜索、已读取页面、回答完整且引用合法时，直接发布并结束；否则执行独立综合。未经校验的决策草稿不再发布为 reasoning 正文，结束进度先于正式正文，综合阶段使用总时限内剩余时间。
4. 重新编译 Sidecar、构建桌面、提交推送并重启。新建“搜索接口对比复测”会话，通过真实 UI 发送新问题。
5. 观察到约 37 秒、3 个步骤后正常结束：两次 Tavily 搜索、一次 Fetch。报告承认返回原文被截断，明确区分搜索摘录与实际读取证据。
6. 用只读 SQLite 核对 `completed`、`research=true`、两条 Tavily 来源、一个 Fetch、零条 reasoning 步骤、最终 text 步骤及已保存正文。重启后重新打开会话，正文和研究标签仍在。

37 秒仅为本次 UI 显示的执行耗时，不是重复采样的速度基准。首轮外部综合失败的底层响应未留存，不将其武断归因于某一个 HTTP 状态。

## PDF：实际选择、发送、视觉回答与保存

1. 新建会话，切换 Chat，关闭 Web Search。
2. 通过系统文件选择器附加仓库的 `browser/synthetic-charts.pdf`，勾选“读取 PDF 图表”，页码填写 `2`。
3. 发送问题，要求只根据第 2 页图像说明柱色、高低和比例，禁止用第 1 页的文字数值替代。
4. 发送后真实看到原 PDF 附件和 `synthetic-charts.pdf [page 2].jpg` 页面图片。回答为左橙红、右绿、右柱更高，约为左柱 1.8 倍，符合测试文件第 2 页几何图形。
5. 数据库存有两个附件：899 字节 PDF 与 18331 字节 JPEG。文件存在，尺寸与记录一致，原 PDF 与仓库样本逐字节一致。
6. 重启最终桌面应用后重新打开“分析PDF第二页柱图”，原件、页面图片及回答均恢复。

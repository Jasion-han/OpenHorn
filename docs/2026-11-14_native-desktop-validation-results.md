# 用户返回后的原生桌面验收与修复

## 状态与证据边界

用户解锁 macOS 后，本轮已实际进入独立 `OpenHorn Native QA` 的 Tauri 窗口，使用原生控件、文件/文件夹选择器、键盘快捷键和真实模型执行核心流程。操作期间读取了可访问树和窗口截图；没有把浏览器 fixture、HTTP 请求或构建成功算作原生操作。

本轮已完成可独立推进的修复、检查和实机复验，实际 GUI 覆盖动作仍需用户在动作前确认，重复原生文件选择保留为未完成项。完整任务不记作“35 项全部通过”：实际覆盖、有限观察、待确认操作与工具层不确定性分别列出。上一份[锁屏阶段报告](2026-11-14_native-audit-results.md)保留为历史证据。

使用独立后端、SQLite 和生成的资料/会话/工作区。原有应用和用户项目没有被替换；真实模型请求使用已有渠道和合成内容，DeepSeek 云端 OCR 未请求。

## 实际操作记录

### 聊天与 Agent

1. 打开原生模型选择弹窗，查看默认渠道/模型，使用 Escape 关闭。
2. 展开模式菜单切换 Chat，关闭联网，粘贴合成中文问题并发送。看到“正在生成”和最终 `NATIVE_DESKTOP_QA_OK`，以及 token 记录。
3. 编辑用户消息、确认重新生成；生成期间切资料库再返回，看到 `NATIVE_DESKTOP_EDIT_OK`。点击重新生成后再加载会话，结果仍保持。
4. 通过原生界面请求长列表，实际点击 Stop。第二次停止测试明确看到部分正文与“已停止生成”，输入区恢复可用。第一次较晚的 Stop 与正常结束存在竞争，未将该次计作取消成功。
5. 使用原生文件夹选择器加入仅含生成文件的 workspace，进入项目范围欢迎页。
6. 实际只读 Agent 返回 `NATIVE_QA_MARKER`，展开步骤能看到该项目的 `qa.txt` 路径。
7. 明确授权只对生成的 qa.txt 追加标记。看到 Read/Write/Read、DONE，文件也确实出现新行。
8. 将这个专用目录临时移至旁边的生成路径，原生发起只读任务，看到“项目文件夹不可用，无法在该目录中运行”。随即恢复目录，没有沿用其他项目的工作区。
9. 新包真实文件修改后出现快照提示；新建会话离开时隐藏，通过统一搜索返回所属会话又出现。恢复入口的最终确认另列边界，未自动覆盖文件。
10. 将真实合成回复保存为成果，工作台显示 `Native QA saved reply`、版本 1 与对应原文。

### 设置、资料库和迁移

- 依次进入通用、渠道、认证来源、Agent、MCP、Skill、数据、外观页面。认证来源如实显示未检测到；Skill 显示磁盘扫描结果，没有修改用户的全局开关。
- 实际展开回答形式与搜索来源菜单，观察浅色默认/选中/聚焦态；用 Down、End、Enter、Escape 操作。保存 DuckDuckGo 来源，看到成功反馈。
- 原生 MCP 新建输入 null、编辑输入数组均被拒绝，草稿仍在；保存合法生成对象、禁用并取消编辑。测试配置未执行网络连接或任意安装命令。
- 打开渠道管理的空白新建表单，选择 DeepSeek 预设，看到官方 Base URL。未填写 Key 时创建按钮禁用，取消没有产生新渠道。既有连接测试只观察到忙碌和恢复，未捕获结果 toast，未记作连接成功。
- 打开资料库上传与 macOS 文件选择器并取消，导入保持禁用，没有残留忙碌。正文资料通过本地 HTTP 预置，**这不算原生文件上传成功**。
- 图片原件的更多菜单中，本地重建禁用，显式 OCR 可用。打开 OCR 确认，传输和费用说明清楚，未勾选时提交禁用；取消没有调用云端 OCR。
- 原生输入 ORCHARD 检索到真实片段，打开正文，再基于资料准备聊天草稿，实际模型回答 `ORCHARD-42` 并引用原文件。
- 原生选择损坏的生成 ZIP，看到“请重新导出后再导入”的中文提示。
- 原生选择有效 DeepSeek v3 生成归档，检测为 DeepSeek，确认导入后显示 1 会话、2 消息；实际历史、侧栏刷新问题由这次操作发现。
- 打开工作台的成果与评论分析页；打开定时任务菜单和手动表单，必填项为空时不能保存，自动启用提示清楚；取消没有建立自动执行任务。
- 通过 CmdQ 退出 QA，进程检查确认宿主及子 Sidecar 退出；重新打开后能读取项目、历史和保存的指令。默认欢迎页与自动恢复到某个会话是两件事，本轮未改为自动选中旧会话。

## 选择器与视觉复验的不确定性

重复原生文件选择时，曾出现文件已选中但系统 Open 仍禁用。换了路径、键盘选择和公开辅助动作后没有稳定完成第二次导入，已取消；不能用此前服务端去重测试补算原生重复导入通过。

为区分 macOS 扩展名筛选与自动化状态问题，做了一次可还原的 QA 构建对照：取消导入选择器的扩展名筛选后，Open 仍禁用。该证据不支持修改筛选规则，实验已按原字节恢复，未纳入产品修复。

快照弹窗的可访问树已出现影响说明和确认/取消控件，但截图没有可靠反映弹窗层。本轮选择将确认直接展开在当前浅黄提示区，减少额外遮罩和焦点切换。最终内联版本已由真实截图确认：影响范围、保留当前文件、确认还原文件同时可见；点击“保留当前文件”后收起，文件未改变。离开会话后入口隐藏，通过统一搜索返回所属会话后重新出现。

## 验证与保留范围

- 新桌面回归 **681 pass / 0 fail**；新增 4 项设置状态测试及 3 项实际导入处理函数测试。导入测试在已发布处理函数上出现 1 pass / 2 fail，在候选实现上 3 pass / 0 fail，覆盖重复提交、迟到结果和失败后重试。
- 原目录三方整合后，typecheck、Biome 与 **711 项桌面测试**通过。711 包含原有未提交功能，发布树仍以独立验证的 681 项为准；其余未提交工作继续保留。
- 最终候选 typecheck、Biome、UI 生产构建及本地未签名 Tauri debug app 构建通过。构建体积警告仍保留，没有为消除提示盲目切包。
- 本轮没有修改服务端/Sidecar 协议实现；上一轮的 1,731 项隔离树测试与 52 项 Rust 结果是已有基线，不能写成本轮重新运行了全部套件。
- 真实 DeepSeek OCR、其他付费工具质量、账户权限、最终账单、实际中文输入法选字、自动调度运行、GUI 删除和 GUI 最终还原未在本轮擅自执行。
- 只读 Agent 与多轮文件修改的累计 usage 分别约 27k/55k tokens。这是回合累计值，下一步应先分解 system/tools/skills/history 和多轮重复输入，再决定预算优化，不凭一次累计值断言某个模块是根因。

逐项操作记录、最终构建指纹和检查摘要已保存在 [native-visible 证据目录](audits/2026-11-14/native-visible/)。记录是按时间追加的观察组，含失败、候选与有限观察，不能把总条数当作全部通过的测试数。原始私有数据库、密钥环境和 provider 事件日志不进入仓库。

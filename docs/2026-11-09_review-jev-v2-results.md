# Jev 说明核对第二轮：建议、问题与事实的边界

2026-11-09。用户要求继续验证改进；全部追加付费实验沿用已确认的1美元累计预算，只发送自编原文和说明。当前规则升级为`review-note-v2`，保留第一轮记录和原始证据。

## 本轮发现与修复

新增20个边界案例后，v1存在两个实际问题：6条纯建议/问题都得到低支持度而被提示复核；“事实总结＋建议”中有1条正确说明被误报。例如“用户反馈大文件导出卡顿，建议收集日志”中的建议不是原文事实，不能因此判定前半句有误。

v2在同一请求中并行问两个Noul：

1. 说明是否包含至少一个可核对的事实陈述。
2. 仅就事实陈述而言，原文是否支持全部事实；建议、问题和操作要求不算事实。

代码持有完整判定表，两个问题都以0.3/0.7为门槛，未按留出结果调阈值：

| 事实存在性 | 支持度 | 界面 |
|---|---|---|
| ≤0.3 | 任意有效概率 | 没有可核对事实；不显示支持百分比 |
| 0.3～0.7之间 | 任意有效概率 | 判断不确定；不显示支持百分比 |
| ≥0.7 | ≤0.3 | 建议复核说明 |
| ≥0.7 | ≥0.7 | 未发现明显冲突 |
| ≥0.7 | 中间区间 | 判断不确定 |

结果仍是辅助信号，不自动改标注、不拦截导出。没有可核对事实不等于建议合理或已验证通过。

## 兼容性与可追溯性

- v1/v2记录都可读取和备份恢复。v2记录必须包含合法的事实存在性概率及匹配的派生状态。v1记录显示旧规则提示，不自动付费升级。
- Native与OpenRouter通道均严格要求两个完整Noul。错误响应、缺头或非法概率不能变成“不适用”或“原文不支持”。
- 缓存请求预览按记录中的resolved model还原实际请求模型；OpenRouter缓存不再显示成Native模型。
- 保留此前的权限、文档/标注版本、原文/说明精确比对、配额预留、成功缓存、修改失效及无自动重试约束。

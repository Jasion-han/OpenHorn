# Jev 第一批接入设计

> 实施阶段方案存档；文中的“不提交推送”仅限当时实施阶段，后续用户已通过 `$ship-flow` 授权提交和推送。实际提交及验证范围见[提交验收](../../2026-11-09_jev-ship-validation.md)。

依据用户阅读全项目报告后“好，那就执行”的授权，实施独立OpenRouter决策层、评论情感/固定主题、欢迎语义去重、Server检索重排、技能建议与联网路由影子评估。其余报告候选保持后续建议，不将全部24项一次上线。

方案：复用原生工作台和设置布局；服务端固定OpenRouter System One端点及Jev 1.14，经验证后私密配置已给的Key。客户端不持有Key，原有直连备注核验迁到OpenRouter。纯判断构造/验证放shared，动作/权限/CAS仍在原代码。考虑过直接塞入普通聊天渠道（协议不符）和全量替换所有启发式（会覆盖用户意图且缺线上评测），选择独立、受控增强。

配置：Agent设置新增可折叠Jev卡片，状态/总开关/各功能开关/当天费用；默认只有配置并明确启用时运行。示例配置无密钥，真实Key仅写Git忽略且0600的server/.env。默认每日$0.05，采用持久保守预留和实际回执结算；失败状态不当no，不自动付费重试。请求限28KB、默认5秒、后台影子2秒；同用户相同输入/候选/版本共享请求并缓存，失败冷却，所有缓存有上限。

评论：显式“Jev快速标注”，独立于聊天准备按钮。不创建虚假会话，保留批次输入/requestId/每行revision；先存pending批次再调用，重复请求不重新付费；结束时跳过已修改行，删除后不得恢复。只生成已有字段的情感与固定主题，quote/note留空或保留已有人工内容，灰区显示待复核。原JSON批次/旧备份兼容，失败批次保留错误可显式新建重试。新metadata按现有JSON文档校验，不改SQL schema。

其他增强：欢迎先生成候选，再语义过滤，同题/不可用回退旧过滤；Server搜索/RAG对有界、已授权候选重排，Jev等待后重查来源存活，失败保留原顺序；技能仅给当前已启用名单建议/优先顺序，不删除未建议技能，显式选择和配方要求保持；路由只记录有限聚合差异，不能改变当前执行或存原始请求日志。

验收：失效/预算/超时/乱形状/同请求去重、备注核验兼容、评论CAS/人工修正/删除/lost ACK、排序来源防复活、技能无匹配/禁用/显式项、影子不改行为；隔离数据库/合成接口完成全套相关测试、浏览器验收和桌面构建。实际Key联通仅少量合成请求，不自动运行真实任务。不Git提交推送。

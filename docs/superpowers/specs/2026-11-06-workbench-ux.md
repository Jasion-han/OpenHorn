# 工作台交互精简与定时任务分工

用户要求调整交互与页面布局，避免臃肿，并与已有定时任务清楚区分。沿用现有视觉系统，选择“工作台复用做法与成果，定时任务统一管理时间安排”的实施方案。

- 配方页只以“运行一次”为主操作。“设为定时任务…”是次级操作，把当前配方版本和参数交接到既有定时任务创建对话框；工作台不再展示频率/时间表单，也不在本页直接创建日程。
- 定时任务页统一创建、启停、改时间及查看运行记录。来自配方的任务显示来源和冻结版本；编辑时不能改冻结prompt/项目/模型，允许改名称、时间和通知。取消交接对话框不创建任务。
- 配方保存参数化做法，不显示任务运行状态和启停开关。工作台有简短分工说明，定时任务页明确它管理自动执行。
- 去掉重复大标题、空状态大虚线卡、选中详情的嵌套大卡；已有配方时模板入口收进“新建”菜单，空列表才展示三个紧凑模板。配方编辑器把项目/模型/工具要求放入可展开的运行设置，基本填写只显示名称、任务说明、参数。
- 产物详情保留名称、版本与主要操作；导出、重命名、删除、查看来源等收进更多菜单。预览/原文轻量切换，内容占主要空间，保持版本CAS和冲突草稿保护。
- 使用现有语义色、字体、Radix/Lucide；窄窗堆叠，不新增导航层级或框架。新增中文只在agent.ts。
- 交接只在内存，按目标页面消费；不因跳转、取消、刷新或迟到请求意外创建/重复创建任务。来自配方的任务必须仍由recipe schedule服务冻结版本/参数，并保留后台能力与租约校验。

验收：真实浏览器验证配方无内联日程、二级操作跳转已有定时任务、取消无写入、确认只有一次创建、来源与冻结字段、普通任务仍可编辑、产物菜单与冲突保稿、深浅/窄窗；Bun定向及完整相关测试、类型/格式检查与桌面打包。用合成API/IPC，不启动真实模型或真实定时任务。

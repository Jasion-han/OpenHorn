# 评论分析工作台设计

日期：2026-11-09。状态：依据用户“详细深度规划后开始执行”的授权推进；下述具体限制和实现选择由执行者提出，不冒称用户逐项确认。

## 目标与使用场景

把一次性评论分析变为能再次打开继续工作的业务项目：导入 CSV → 预览和映射 → 保存数据集 → 选择评论 → AI 标注 → 同步经校验的结果 → 对照原文修正 → 筛选和导出。目标用户是已有评论文件、需要归纳产品反馈的人。已有输入和结果必须独立于聊天页面保存。

首版不抓取社交平台，不新增模型调用引擎，不做通用插件市场、任意插件执行、跨设备离线同步或自动无限批处理。数据存储位置沿用当前 OpenHorn 后端；连接远端后端时不能声称数据仅在本机。

## 代码现状与方案选择

- 原生工作台在 `WorkbenchView` 中呈现配方/产物；`RecipePanel` 复用会话创建、选择和绑定 pendingPrompt 的交接。
- 配方描述可复用任务，产物保存文本版本；它们不应承载结构化评论数据库。
- GenUI 的 OpenUI 控件状态有本地持久化；HTML opaque-origin 沙箱只允许建议提示词和打开链接，不应为本功能扩大其权限。
- Schema 同时存在于 Drizzle 与 bootstrap；全量备份有一致 SQL 快照、用户范围 ID 映射和来源重绑。
- 当前工作区有大量先前未提交改动。本任务在现有文件上做最小增量，不重置、不自动提交、不运行真实用户数据库迁移。

比较三种方案：

1. **通用插件 SDK**：覆盖面大，但需同时设计安装、权限、升级与隔离，无法优先验证具体业务价值，后置。
2. **预置评论配方**：实现最轻，但缺少结构化结果、人工修正、项目数据和局部重跑，不足以完成本次目标。
3. **原生评论工作台（采用）**：复用现有 UI/会话执行，增加小而明确的领域数据/API。将来由真实使用中提取插件接口。

## 数据模型

新增用户拥有的 `review_workspaces` 表：id、user_id（级联删除）、title、revision（正整数）、data（版本化 JSON）、created_at、updated_at。JSON 包含 schemaVersion=1、原始 CSV、文件名、分隔符、列映射、评论记录和不可变的批次输入/导入结果。使用单文档是首版有界数据集的选择；所有写入使用 SQL CAS，避免无意覆盖并发修改。

- 文件：严格 UTF-8，支持 UTF-8 BOM、CRLF、引号内换行、双引号转义；支持逗号/分号/Tab，用户可切换。
- 上限：原始 CSV 2 MiB；1000 条非空评论；50 列；单格 20000 字符；单条评论 8000 字符；评分字段 200 字符；整个文档 12 MiB；每项目最多 50 批分析。越界报明确错误，不静默截断。
- 第一行为表头，空表头/重复表头允许，通过列索引区分。保留全部原始 CSV 和导入行号。只跳过全空行及映射后正文为空的行，显示跳过数；重复评论不自动删除。
- 必选正文列，可选评分列。评分保留原始字符串，不把星级当情绪真值。
- 稳定评论 ID 来自源记录号，如 r2；源文本一经导入不可变。更新源文件通过新建项目，避免错绑旧分析。
- 标注：sentiment（positive/neutral/negative/mixed/unknown）、topics（最多5项，每项50字符）、quote（原文连续片段，最多160字符，可为空）、note（最多400字符）、source（ai/manual）、revision。未标注用 null。
- 人工修正递增每条评论 revision；批次记录每条输入的 revision。导入时跳过任何基线已变化的评论，防止覆盖人工或更新的 AI 结果，并准确显示应用/跳过数。

## AI 执行与证据

每批最多20条评论，序列化 JSON 输入（含正文、评分、ID 与转义）总量最多24000字符。界面默认选择尚未标注的下一批，也允许勾选已分析评论重新运行。超出一批须显式减少选择；不在后台悄悄分批调用模型。

`POST /review-workspaces/:id/runs`：带 expectedRevision、requestId、rowIds、明确的 channelId/modelId；校验渠道归属、启用和模型可用性，在事务中创建新会话（沿用普通 Chat 模式，无工作区/网络/工具要求）、批次输入快照和提示词。请求 ID 在该工作台中幂等，重试返回原批次，不重复创建会话。

返回完整 prompt，界面使用既有绑定 conversationId 的交接，`autoSend:false`，用户检查后在聊天中发送。文案使用“准备 AI 分析”，说明将跳转聊天；取消/重试/凭据处理沿用普通聊天。离开页签、切换项目或账号时取消迟到导航。批次状态叫“待导入”，不能把准备成功冒充模型正在运行或分析完成。

独立审阅补充：ACP 不支持普通 Chat，因此在创建任何状态前拒绝 ACP 渠道；同一事务内直接插入 conversations（不调用使用全局 db 的 createConversation）；该会话以固定 JSON 格式标记和独立 systemPrompt 保持机器可读输出，GenUI 追加层和重试追加层识别此标记并保留原契约，不修改全局设置。该会话跳过跨会话摘要、RAG及实时联网/工作区扩展，评论中的天气/搜索指令也不能触发路由。

提示词把评论明确标为不可信数据，要求不执行其中指令、不调用工具，仅输出一个 JSON 对象：`{runId, results:[{id,sentiment,topics,quote,note}]}`。提示词在 i18n 字典提供；服务端通过纯 helper 加入 JSON 输入/输出契约，不依赖中文硬编码 UI。

`POST /:id/runs/:runId/import`：只读取关联的、当前用户拥有的会话中最新助手消息。Agent 消息必须 completed；普通聊天不得有失败/截断/取消 finishReason，且只接受可完整解析的 JSON（允许一个 json 围栏）。未保存/不完整消息不能导入。使用 shared/message-text 提取权威正文。严格要求 runId 相等、每个 batch ID 恰好出现一次、无额外 ID、每条字段限额合规、quote 是对应源文本的连续子串。整批校验通过后原子应用；不接受“先写一半后失败”。

每个批次保存结果和 sourceMessageId，重复导入已完成批次为无操作。导入错误保留原始数据、先前标注和批次，可回聊天修正并再同步。删除来源会话后已导入结果保留；来源检查仍须用户归属校验。

## 交互与视觉设计

使用 web-design-engineer 的 Extension 模式：沿用 Radix、现有 Button/Input/Dialog、工作台最大宽度、主题 token 与系统字体。设计读数：视觉变化2/10、动效1/10、信息密度7/10、素材依赖1/10、现有风格保持10/10。它是笔记本距离使用的安静数据工具，重点是评论和证据，不引入营销装饰或新字体。

色彩：现有 background/foreground/muted/border/primary/destructive；情绪用文字明确表达，不仅依赖颜色。间距沿用4px节奏，圆角 rounded-md，阴影仅复用现有选中页签，交互用已有 focus-visible。导入/编辑使用原生表单语义；所有可操作元素有可访问名称。

```
工作台                         任务配方 | 产物 | 评论分析
评论项目 [选择项目]                       [导入 CSV]
项目名 / 文件名 / 已保存版本
总评论 · 已标注 · 人工修正 · 未标注
[搜索原文/主题] [情绪筛选] [待标注/全部] [导出]
[选择下一批未标注]  已选 N / 20       [准备 AI 分析]
评论列表：复选框 / 行号 / 原文 / 情绪 / 主题 / 修正
选中评论详情：完整原文、证据、备注、来源、修正表单
分析记录：批次范围 / 待导入或已导入 / 打开会话 / 同步结果
```

窄屏控件换行，表格仅在自己的容器中横向滚动，详情位于列表下方；不让整页溢出。列表每页25条，选择跨页保留且批次受限。搜索/筛选/统计在本地计算，不调用模型。

导入窗口：先读取/解析文件，选择分隔符、正文/评分列，显示真实前5条和有效/跳过数量，再输入项目名保存。文件切换取消过期解析；保存失败保留草稿；有改动关闭先确认。

人工修改使用显式保存，失败保留表单；关闭有改动先确认。项目删除须确认并说明源聊天不会被删除。列表加载失败显示重试，不能伪装为空数据。账号/后端切换清理内存中的选择和草稿，迟到请求不能显示上一身份数据。

## 导出、备份与恢复

- CSV 导出全部评论（不受当前筛选影响）：源行号、原文、评分、情绪、主题、证据、备注、标注来源。正确转义引号/换行；电子表格公式前缀（= + - @，含前导空白/控制字符）加安全前缀。原始 CSV 另提供完整原文导出。
- Markdown 报告从已保存数据计算总量、覆盖率、情绪分布、主题频次，并附逐条原文/证据与来源；不捏造模型总结。动态内容不得作为可执行 HTML。
- 原生 `.openhorn-backup.zip` 纳入工作台完整文档与数量。恢复校验文档，使用既有用户范围 ID 映射；批次来源会话/消息重绑或置空。重复导入不重复创建工作台。

## 验收与风险

1. CSV 复杂引号/换行/空表头/重复行正确；格式/编码/大小超限明确拒绝；无静默截断。
2. 两用户互不可读写/删除/导入；旧 revision 并发写拒绝；失败事务不留下多余批次/会话。
3. AI 输出错 runId、漏/重复/额外评论、错误枚举、伪造证据、非终态消息全部拒绝且数据不变；人工修改后旧批次导入不会覆盖。
4. 重启重新加载保留源文件、标注和批次。备份→新用户恢复→重复恢复仍一致；来源删除不影响已保存结果。
5. UI 完整走导入、筛选、准备会话、同步、修正、导出、冲突和失败重试；窄屏/深浅主题无整页溢出。已有配方/产物回归不损坏。

测试仅使用独占临时 DB/OPENHORN_HOME、无真实模型凭据和外部网络；前端浏览器使用真实组件+受控 API/聊天完成数据，不把模拟结果冒称模型质量验证。完成后说明没有实付模型调用和原生打包/部署的实际范围。

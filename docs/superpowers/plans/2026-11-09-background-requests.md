# 后台请求与设置同步优化计划

本轮继续用户已授权的系统性优化，由当前会话逐项实施，不提交或部署。

目标：避免异常向量污染检索、欢迎推荐失败连续调用、旧身份请求回写，以及 Agent 设置重连覆盖编辑。

方案：沿用现有接口和布局，增加请求边界与版本守卫。推荐保留 12 小时缓存和现有 seed；失败后冷却 60 秒。向量请求默认 15 秒超时，支持调用方取消，只接受每条输入对应一个 1536 维有限数向量；支持全部带 index 或全部不带 index 的兼容返回。设置密钥草稿只存在当前组件内存。

- [x] 向量：`embeddingService.ts` 增加超时、取消、数量/维度/index 校验；合成 fetch 验证乱序、畸形数据、超时和取消，不调用真实服务。
- [x] 推荐后端：`welcomeSuggestionService.ts` 通过依赖注入测试每用户并发去重、失败冷却、恢复和保留旧缓存；不改变数据库结构和缓存 seed。
- [x] 推荐前端：`welcomeSuggestionStore.ts` 增加 reset、定时器清理、身份/请求代次守卫；延迟响应不得恢复旧数据。启动推荐读取等待身份加载完成，避免新缓存被身份重置清空。
- [x] 设置：`AgentSettings.tsx` 在首次成功加载前禁用编辑并提供重试；重连保留草稿；加载与保存不能互相覆盖；保存中禁用重复操作，失败保留输入。扩展合成浏览器验收。
- [x] 完成 Server/Desktop 全套测试、全仓类型/格式检查及相关浏览器验收；构建新版桌面端；记录证据和现有限制。

审查重点：混合/重复 index、响应体读取也需超时、重置后旧 finally 不得清新请求、重连发生在输入中/写入中、首次加载失败不能显示假配置状态。所有测试数据库隔离，真实密钥不输出。

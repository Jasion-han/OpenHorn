# 研究重试与文档缓存边界修复

本轮沿用现有交互和运行方式，修复实际复现的问题；不增加搜索源、工具权限或后台收费重试。

1. 研究重试在没有新正式报告时，失败或停止均保留此前成功报告。普通 Agent 的文件/工具步骤仍按原约定保存。用纯状态回归和真实 Chat 组件覆盖失败、停止、成功替换与重新加载。
2. 已完成检索后的报告式决策允许在 180 秒总时限内等待最多 60 秒；区分模型单次超时、报告为空、输出截断和引用校验失败，不暴露服务商原始敏感响应。
3. 消息操作栏保持浅色与低对比，但默认可见可点，消除从完全隐藏到可点击的首次点击竞争。
4. 文档缓存单条上限由 8 MiB 调整为 12 MiB，覆盖六张上限图像的 Base64 编码和必要文字开销。账户仍为 50 MiB、有效期 7 天，不因额度不足删除未过期快照；用 cursor 清理过期数据并统计额度，避免 getAll 加载全部账户图像。存储打开/事务失败统一为 document_cache，保证发送流程恢复草稿和原文件。
5. 上传回执除数量、文件名、大小和 ID 外，校验已知 PDF/图片的类型，拒绝错误身份。

验收：先证明新增回归失败，再修复；运行 Desktop/Sidecar 相关与全量测试、浏览器实际组件和真实 IndexedDB 回归、类型/Biome；重建并在原生桌面实践重试/停止与报告保留。保留用户需要查看的真实验收会话，清理临时夹具和测试库。按已授权 ship-flow 分批中文提交并推送。

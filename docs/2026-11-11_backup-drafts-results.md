# 备份容量与聊天草稿衔接

本轮继续可靠性优化，修复两条数据保留路径；未提交、推送或部署，未操作真实业务库或调用外部模型。

## 备份导出与恢复采用同一上限

导出和恢复共用ZIP限额：每个未压缩条目128MiB、总计512MiB、20000条目。导出先校验完整JSON的UTF-8字节数与附件实际文件大小，写入时再次统计原件流的真实字节。原文件在预检后增大、消失或输出失败均不能留下被报告为成功的半成品；附件逐个读取，避免同时打开大量文件。超限返回413及backup_size_limit，桌面显示本地化说明并提醒保留原数据。

测试覆盖正常往返、原件消失、输出文件创建失败、版本一致快照，以及128MiB+1稀疏文件预检拒绝、源文件预检后增长导致流式拒绝及半成品清理。还测试了单条目/重复名称及累计实际字节预算。

## 聊天草稿留在对应会话

已存在会话的输入文字和待发送File对象保存在本次登录内存，按后端/账号/会话隔离。切页/切会话后恢复；退出登录或重启清空，不自动发送。重新打开资料问答时，优先保留用户已经改过的问题，不能用原始来源提示覆盖。

自动交接若与已有未发送内容冲突，会保留两份文字并要求检查后发送。异步附件处理只清理它原来负责的文件，不影响后来选择的附件或其他会话。删除会话或项目成功后释放对应草稿，失败保留；账号代次和会话版本阻止删除/账号切换前的迟到回调重建草稿。

真实浏览器使用独立合成后端，验证离开聊天后恢复文字与附件、重复资料问答交接不覆盖、不误发送、不同会话独立草稿、退出账号清理。欢迎页尚未创建会话的输入仍沿用原行为，本轮不声称它已纳入会话草稿。
